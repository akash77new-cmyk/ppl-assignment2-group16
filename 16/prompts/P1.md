## Unit 3 — `satisfies/2` and `count_solutions/2`

> Write `satisfies(Active, Solution)` and `count_solutions(Active, N)`.
> `Active` is a list of clue numbers; clues not in the list must be ignored
> entirely. Use `findall/3`.

**Returned, first attempt:**

```prolog
satisfies(Active, Solution) :-
    maplist([N]>>clue(N, Solution), Active).
```

**REJECTED — this is wrong, and it fails silently.** `yall` copies the lambda
body on every call, so the free variable `Solution` is renamed to a fresh
unbound variable and the clues are tested against nothing. The symptom was
`solve([1,2,3], S)` failing outright while every clue passed individually
against a hand-written solution.

> That fails. `solve([1,2,3],S)` gives no solution even though each clue
> succeeds on a solution I supply by hand. Diagnose it and fix it.

**Returned:** diagnosis (yall copy semantics; it needs
`{Solution}/[N]>>clue(N, Solution)`) and the replacement

```prolog
satisfies(Active, Solution) :-
    forall(member(N, Active), clue(N, Solution)).
```

**Accepted**, with the explanation kept as a comment in the source so the trap
is documented where the next reader will meet it. Added to the prolog-dev
skill as failure mode 1.

## Unit 7 — the test file

> Write `tests/test_q1.pl`. Cover the count for clues 1–8 and 1–9, the three
> expected solutions exactly, clue 9 true in B and false in A and C, and the
> output shape of `main/0`.

**Returned:** a `check/2` harness plus assertions. Two of them failed on the
first run:

- `findall(S, solve(...), Got)` reused `S`, which was already bound earlier in
  the clause, so it collected three copies of one solution instead of the three
  solutions. **Rejected and fixed** by renaming the variable.
- `sub_term('Alex', Body)` was used to check that clue 9 names no friend. It
  succeeds against *any* term containing an unbound variable, because the
  variable unifies with `'Alex'`. **Rejected entirely.**

> Replace the `sub_term` check with something that actually tests the property.
> Being name-free means the clue's truth cannot depend on which friend holds
> which triple.

**Returned:** a semantic test that keeps solution B's four attribute triples
fixed, relabels them with all 24 permutations of the names, and requires clue 9
to hold in every one.

**Accepted.** This is a stronger test than searching the source text. Both
rejected versions were added to the prolog-dev skill as failure modes 5 and 6.
