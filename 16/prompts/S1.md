## Unit 1 — the inorder traversal

> Write only the inorder traversal helper for `16_q3.rkt`. `append` is
> forbidden, so it has to be an accumulator-passing helper:
> `(inorder tree acc)` returns the inorder values of `tree` followed by `acc`.
> A tree is `'()` or `(value left right)`. Check your function against the
> allowed-built-ins list in the scheme-dev skill before answering and tell me
> which built-ins you used.

**Returned:**

```racket
(define (inorder tree acc)
  (if (null? tree)
      acc
      (inorder (cadr tree) (cons (car tree) (inorder (caddr tree) acc)))))
```

with a statement of the built-ins used: `define`, `if`, `null?`, `cons`,
`car`, `cadr`, `caddr` — all on the allowed list.

**Accepted.** The contract sentence "returns the inorder values of tree
followed by acc" is what makes the definition obviously right, so it was kept
as the comment.

## Unit 2 — preorder and postorder

> Now the preorder and postorder helpers in the same accumulator style.

**Returned:** both, with the same shape — preorder conses the node first then
threads the accumulator right-to-left; postorder threads the node into the
accumulator before descending.

**Accepted.** Verified by hand on the right-leaning tree
`(1 () (2 () (3 () ())))`, where inorder and preorder coincide at `(1 2 3)`
but postorder is `(3 2 1)` — a case that catches an accumulator threaded in
the wrong order.

## Unit 3 — height and leaf count

> Write `height` and `leaf-count`. Height of `'()` is 0 and a single node has
> height 1. A leaf is a node whose two subtrees are both `'()`; the empty tree
> has no leaves. `max` is allowed.

**Returned:** both, with `leaf-count` using `cond` and testing the
both-subtrees-empty case before the recursive case.

**Accepted.** The order of the `cond` clauses matters: `null?` must be tested
before the leaf test, or `(cadr '())` is evaluated on the empty tree.
